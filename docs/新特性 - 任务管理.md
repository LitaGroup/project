接下来，我想增加一个`任务处理中心` 的功能，任务由Agent来完成，并最终由人来验收和审核。



几个定义：

1. 执行器 - 实际执行任务的工具，具体指：opencode、codex、claude code 等，本次任务只用opencode。
   1. 一个执行器包括几组属性：
      1. ip - 部署在哪台机器上
      2. port - 对外开放的端口号
      3. type - opencode
      4. description - 描述
2. 供应商 - 这里是大模型的供应商，直接从 执行器 的命令行中获取，本地可以缓存一份
3. 机器人 - 可以是具体的员工，也可以是具体的智能体，如果是智能体，完成任务的最小智能体，一个智能擅长一件事情，比如：需求分析师（判断需求是否完整、是否有需要补充的素材等）、技术架构师、前端架构师、后端架构师、客户端架构师、发布工程师、前端工程师、UI工程师、后端工程师 等等
   1. 一个智能体，背后有一个责任人，这个责任人来负责 定义 智能体，并对智能体接收的任务进行反馈、验收，一旦负责人验收通过，则意味着这个任务处于`内部完成` 状态
   2. 智能体需要定义：
      1. 选定执行器 + 供应商 + 模型
      2. 一段角色定义的 PROMPT
      3. 技能清单（直接提供技能的 MD 文件，或者 命名）
      4. 负责人  实际的负责人的员工
      5. 简介：需要描述清楚，擅长什么，可以完成哪些任务，以便于 外部是否选择这个智能体来干活
      6. 任务：可以有多种类型的任务定义，每个任务需要明确输入（即：提供什么）、输出什么，通过什么方式来完成
4. 任务包 - 具体需要执行的任务内容，需要明确：当前任务的输入有哪些、明确输出是什么
   1. 任务 可以被拆分成子任务，即：任务下面可以挂载子任务
   2. 任务 - 需要有明确的任务类型
   3. 任务 有状态 - 
      1. 创建阶段 - 识别任务的类型、查看是否缺少某些素材，需要补充清楚，材料完整后可以进入下一阶段，并可以将缺失的清单也附上
      2. 分发阶段 - 
      3. 执行阶段 - 
      4. 交付阶段 - 
      5. 维护阶段 - 进入维护阶段，表示这个任务是结束的状态。表示不再维护。
5. 调度器 - 项目负责人的角色，根据任务包的内容和类型，以及当前拥有的机器人，对任务进行分配，分配后，由管理员确认后，则任务可以进行派发
   1. 调度器分配任务，需要完成：
      1. 任务识别 - 识别是什么类型的任务，当前的输入、输出是什么
      2. 任务拆解 - 任务是单一机器人就能完成的，还是需要一整个工作流来完成，如果需要工作流，则需要任务进行拆解，形成工作流，并创建多个子任务，进行分包派发
   2. 调度器 需要一个具体的负责人，这个负责人来对任务的派发负责，以及定义和提供调度所需要的材料



在显示效果上，我想可以实时看到：

1. 任务 概览视角，可以看到当前有多少个任务，以及任务的执行状态，能够有动画效果看到任务的子任务、工作流等
2. 工作 概览视角，可以看到每个智能体，当前的试试状态（空闲中、工作中、等待中、验收中），以及当前工作中的实时日志
