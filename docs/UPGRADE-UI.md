# Framer Motion UI 动画升级方案

> 本文仅提供改造方案，不包含代码实现。方案基于 2026-10-26 的前端页面与交互结构整理；当前 `frontend/package.json` 尚未引入 Framer Motion。

## 一、背景与目标

当前平台以高密度表格、项目聚合详情、实时任务和脚本运行页面为主，已有动画较少，主要包括：

- `Terminal` 运行光标的 `animate-pulse`。
- 工作概览中“工作中”状态的 `animate-pulse`。
- 项目详情部分行内编辑、筛选标签的颜色过渡。
- 文档标题定位使用原生平滑滚动。
- Appica UI 弹窗、下拉菜单等组件自身的内部过渡。

本次升级不建议做“全站元素飞入”，而应围绕以下目标展开：

1. **上下文连续**：路由和顶级导航切换时，让用户明确当前所在位置。
2. **状态可感知**：任务、运行、缺陷、机器人等关键状态变化有明确但克制的反馈。
3. **操作有回应**：新增、删除、复制、展开、行内编辑等操作具有自然的视觉衔接。
4. **风格统一**：动画时长、位移、缓动和减弱动态策略集中管理，避免各页面自由发挥。
5. **性能与可访问性优先**：不牺牲高频日志、轮询列表、大表格和表单编辑的稳定性。

### 1.1 非目标

- 不调整现有信息架构、路由、接口、数据结构和业务流程。
- 不用 Framer Motion 重做 Appica UI 已有的 Dialog、Select、Dropdown、Tooltip 等基础交互。
- 不引入营销页式滚动视差、大幅缩放、持续漂浮、粒子或庆祝动画。
- 不对所有表格行、终端日志和轮询卡片统一添加进出场动画。
- 不以动画替代文字状态、错误提示、加载状态或无障碍语义。

## 二、总体改造策略

### 2.1 优先级定义

| 优先级 | 定义 | 实施原则 |
|:---|:---|:---|
| P0 | 全站基础设施与约束 | 最先完成，后续所有页面复用 |
| P1 | 核心业务路径，动画能直接提升状态感知 | 第一批页面改造，优先验证价值 |
| P2 | 操作反馈和局部浏览体验优化 | 核心场景稳定后逐步覆盖 |
| P3 | 装饰性较强、业务收益较低 | 最后实施，可不做 |

### 2.2 建议动画语言

以下为设计目标，实施时应集中为 motion presets，不在各页面散落时长和缓动字面量。

| 场景 | 推荐效果 | 建议节奏 | 说明 |
|:---|:---|:---|:---|
| 页面进入 | 透明度 + 4～8px 轻微纵向位移 | 120～180ms | 仅内容区进入，不移动应用壳 |
| 顶级导航 | 共享 `layoutId` 的选中背景滑动 | 180～240ms | 保持文字和布局稳定 |
| 状态切换 | 旧值/新值轻量 crossfade | 120～160ms | 仅在状态值变化时触发 |
| 小列表增删 | 单项透明度 + 小位移，必要时局部 `layout` | 140～220ms | 只用于稳定 key、有限数量的列表 |
| 条件卡片出现 | 透明度 + 小位移 | 140～200ms | 用于调度方案、产物、失败项等摘要 |
| 折叠区域 | 高度 + 透明度 | 180～240ms | 只用于原始输出等小区域，不包高频日志内容 |
| 数字变化 | 新旧数字短 crossfade 或小位移 | 120～180ms | 只用于统计值变化，不做持续滚动数字 |
| 实时状态高亮 | 边框/背景一次性强调后恢复 | 400～700ms | 必须基于前后数据 diff，不按轮询次数触发 |

默认使用平缓 ease-out；删除确认、危险操作、工作流状态切换不使用夸张弹簧。位移动画优先使用 `transform`，避免大面积 `width`、`top`、`left` 动画。

## 三、页面改造清单

### 3.1 全站框架与公共组件

| 优先级 | 位置 | 改造内容 | 关键约束 |
|:---|:---|:---|:---|
| P0 | `frontend/src/main.tsx` | 接入统一 `MotionConfig reducedMotion="user"`；评估 `LazyMotion + domAnimation`，减少首屏动画运行时成本 | 保留 `StrictMode`、`ThemeProvider`、`AuthProvider`；不改变 Provider 的鉴权与主题职责 |

| P0 | `frontend/src/index.css` 与公共 motion presets | 集中定义动画预设；补充现有 CSS pulse、原生 smooth scroll 的减少动态策略 | `MotionConfig` 不会自动关闭 Tailwind `animate-pulse` 或原生 `scrollIntoView({ behavior: 'smooth' })`，需分别处理 |

| P2 | Appica Dialog、AlertDialog、Select、Dropdown | 保留组件库现有打开/关闭、Portal、焦点管理和键盘行为；仅在业务内容确有需要时动画内部动态区域 | 不在组件外简单再包 `AnimatePresence`，避免视觉关闭与焦点解锁不同步 |

## 四、公共能力设计

建议按需沉淀以下能力，不要在第一阶段一次性抽象所有组件。

| 建议能力 | 用途 | 使用限制 |
|:---|:---|:---|
| Motion Provider | 统一 reduced-motion、LazyMotion 和全局行为 | 接入入口，不改变鉴权、主题和路由职责 |
| Motion Presets | 统一页面、状态、列表、折叠的 transition/variants | 页面不私写一套动画参数；颜色、圆角继续使用 Appica 角色 token |
| `PageTransition` | 内容区轻量进入 | 不包整个 Layout；不阻塞新页面数据请求和挂载 |
| `NavActiveIndicator` | 顶部及必要时侧栏的共享选中背景 | 顶部和侧栏使用不同 `layoutId` 命名空间，避免串场 |
| `StatusTransition` | Badge、连接状态、操作结果的值变化过渡 | 首屏不播、值不变不播，保留文本语义 |
| `AnimatedNumber` | 任务阶段统计等低频数字变化 | 不用于每秒耗时，不用于轮询中未变化的数字 |
| `CollapsibleRegion` | 原始输出、git 输出等条件区域展开 | 仅小区域；内部高频内容本身不做动画 |
| `LiveChangeHighlight` | 机器人、APP、仓库等实时/同步变化高亮 | 必须比较前后值，不能以 render 或请求完成作为触发条件 |
| `AnimatedList` / 表格行适配 | 小列表和运行动态历史增删 | 仅在出现第二个真实使用场景后抽象；大表禁用 |

### 4.1 表格 DOM 与 Appica 兼容要求

- 不得为了包裹 `motion.div` 而在 `<tbody>` 内插入非法 `<div>`。
- 如确需行动画，先验证 Appica `TableRow` 是否可正确传递 `ref`、样式和 motion props；必要时评估 `motion.create(TableRow)`。
- 无法保证表格语义时，只动画单元格内部元素，或直接放弃该行动画。
- React 19 下 `ref` 可作为普通 prop，但仍需确认第三方组件是否继续向底层 DOM 传递。

### 4.2 动画触发原则

1. **按业务值变化触发**：状态、数量、选中项、列表 ID 集合变化才触发。
2. **不按请求完成触发**：轮询和 reload 成功不代表可见数据发生变化。
3. **首屏与更新分离**：首次进入动画和后续增删动画采用不同策略。
4. **稳定 key 是前置条件**：动态增删、重排前必须消除索引 key。
5. **不阻塞交互**：新页面、编辑器、菜单和按钮不能等待旧内容 exit 完成后才可用。

## 五、性能与可访问性边界

### 5.1 高频更新区域

- SSE 终端和运行日志：不逐行动画，不对整个状态卡随每条消息闪烁。
- 工作概览 5 秒轮询：只处理 diff 后的真实变化。
- 运行页每秒耗时：保持普通文本更新，不做数字动画。
- 输入即筛选：不为每次键入执行整表 enter/exit。
- 大列表：不添加全量 `layout`，不创建大量 motion 节点。

### 5.2 滚动与布局

- `Layout.tsx` 中实际滚动容器是 `<main>`，不是 `window`；后续如使用滚动触发动画，必须绑定正确容器。
- 页面进入不做横向大位移，避免宽表格页面出现横向溢出。
- 不为 `AnimatePresence` 随意改变现有编辑器 key，避免额外重挂载、丢失输入或重复订阅 SSE。
- 终端维持原有滚动锚定逻辑，不将自动滚底改为平滑滚动，避免与用户回看日志冲突。

### 5.3 减少动态效果

- Framer Motion 动画统一受 `MotionConfig reducedMotion="user"` 或 `useReducedMotion()` 控制。
- reduced-motion 下取消位移、缩放、布局和持续 pulse，保留必要的状态文字与即时切换。
- 原生文档滚动在 reduced-motion 下改为即时定位。
- 动画不是唯一反馈渠道；复制、导入、同步、成功和失败均需保留文字或可访问的状态提示。
- 弹窗与菜单的键盘焦点、Esc 关闭、焦点返回不得受动画影响。

## 七、验收清单

### 7.1 功能与视觉

- [ ] 快速连续切换顶部 Tab、侧栏和详情路由时，无内容阻塞、错位、横向溢出或指示器串场。
- [ ] 项目搜索连续输入、任务筛选和大表翻页时，列表不追赶动画，焦点和滚动位置稳定。
- [ ] SSE 高频输出时终端无逐行动画，运行状态与进度仍清晰更新。
- [ ] 工作概览持续轮询时，只有真实变化的卡片反馈一次，未变化卡片保持静止。
- [ ] 项目详情连续修改属性时，不重播十个业务板块的进入动画。
- [ ] 提测、代码分支和缺陷图片反复增删时，不错位、不误删、不串用输入状态。
- [ ] Dialog、Select、Autocomplete、Milkdown 的键盘、焦点、输入与关闭行为不回归。

### 7.2 可访问性与性能

- [ ] 系统开启“减少动态效果”后，无持续 pulse、平滑滚动、位移或缩放入场，功能与状态信息完整。
- [ ] 复制、成功、失败和状态变化不只依赖颜色或动画表达。
- [ ] 动画优先使用 `transform/opacity`，无大范围布局抖动和明显累计布局偏移。
- [ ] 首屏与典型页面构建体积和加载表现有前后对比；LazyMotion 未造成功能缺失。
- [ ] 开发环境 StrictMode 下不依赖副作用记录“已播放”，不出现难以维护的重复触发逻辑。
- [ ] 实施后执行 `pnpm lint`、`pnpm build`，并完成上述高频与表单场景人工回归。

## 八、主要风险与应对

| 风险 | 典型表现 | 应对方式 |
|:---|:---|:---|
| 动画过多 | 页面显得吵、操作变慢 | 只动画有业务意义的变化；静态装饰放最后且可裁剪 |
| 高频重渲染放大 | SSE、轮询、每秒计时造成卡顿 | 动画绑定值 diff；终端不接入 motion；大表不做 layout |
| 整体 reload 重播 | 项目改一个字段，全页卡片重新进入 | 不使用数据对象身份作为动画 key；区分首屏与业务增删事件 |
| 表格语义破坏 | tbody 出现非法元素、行列样式异常 | 先验证 Appica 行组件适配，必要时只动画单元格内部 |
| 弹窗焦点异常 | 视觉已关闭但焦点仍锁定，或 exit 不执行 | 保留 Appica 生命周期，不重复包裹 Portal/AnimatePresence |
| 编辑器状态丢失 | 输入中断、内容重挂载、重复订阅 | 不对 Milkdown 本体 crossfade，不用动画改变其 key |
| 动态列表错配 | 删除一行后输入值或图片错位 | 动画前先改稳定 ID，禁止索引 key 参与重排 |
| reduced-motion 覆盖不全 | CSS pulse 和原生平滑滚动仍持续 | 分别处理 Framer Motion、Tailwind CSS 和原生滚动三条路径 |

## 九、结论

本项目最适合的动画升级方向是“**状态驱动、局部反馈、全局克制**”：

1. 全站先统一导航、页面进入和减少动态策略。
2. 第一批优先改造任务中心、工作概览和脚本运行页，直接强化平台核心的 Agent 执行体验。
3. 第二批改造项目详情与缺陷工作流，提升高频操作的连续性。
4. 全局表格坚持“整体轻反馈、单行按事件、筛选不逐行动画”。
5. 终端、SSE、轮询、大列表和编辑器设置明确禁区，确保动画升级不以性能和可用性为代价。
