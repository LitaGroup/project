# 开发验收环境

开发验收环境用于验证 `test` 分支的代码变更，地址为 <http://work-test.agent.cinta.team>。生产环境保持独立，两者不共用数据库、令牌和任务数据。

## 架构

| 组件 | 说明 |
| --- | --- |
| 代码目录 | `/home/ecs-user/work/litawork`，跟踪 `origin/test` |
| 前端 | 构建产物发布到 `/var/www/work-test.agent.cinta.team`，由 nginx 提供静态文件，SPA 路由回退到 `index.html` |
| 后端 | NestJS `backend/dist/src/main.js`，监听 `127.0.0.1:3100`，由 systemd 托管 |
| 数据库 | 本机 PostgreSQL 17 + pgvector 容器 `pgvector`，数据库 `lita_project_dev` |
| 反向代理 | nginx 站点 `work-test.agent.cinta.team`，转发 `/api`、`/images`、`/export-files`、`/files` |
| 运行模式 | `NODE_ENV=development`，TypeORM `synchronize` 自动同步开发库结构 |
| 机器人工位 | `WORKER_BASE_DIR=/home/ecs-user/runtime`；开发环境工位为 `/home/ecs-user/runtime/worker-dev/{workerId}`，与生产 `worker/` 目录隔离 |

开发环境使用独立数据库，只用于功能验证，不执行 `main`/`stable` 发布。当前飞书应用与生产共用（仅用于登录与通讯录同步），业务数据仍为空库；不要在开发环境配置生产群 webhook。

## 首次初始化

以下命令均在目标服务器执行。

### 1. 准备数据库

```bash
sudo docker exec pgvector psql -U postgres -c "CREATE DATABASE lita_project_dev"
sudo docker exec pgvector psql -U postgres -d lita_project_dev -c "CREATE EXTENSION IF NOT EXISTS vector"
```

数据库口令来自部署环境注入的 `DB_PASSWORD`，不写入仓库。

### 2. 准备代码与配置

```bash
mkdir -p /home/ecs-user/work
cd /home/ecs-user/work
git clone git@github.com:LitaGroup/project.git litawork
cd litawork
git checkout -b test origin/main
git push -u origin test
cp deploy/dev/env.example backend/.env
# 按实际环境编辑 backend/.env：数据库口令、AUTH_JWT_SECRET、飞书登录凭据等

# 检查/导出脚本目录（只读同步，供脚本库与联想使用）
git clone git@github.com:LitaGroup/scripts.git /home/ecs-user/work/lita-scripts
```

`AUTH_JWT_SECRET` 使用随机值，例如 `openssl rand -hex 32`；真实令牌和口令只写入服务器上的 `backend/.env`，不提交仓库。

### 3. 安装依赖并构建

```bash
export PATH="$HOME/.npm-global/bin:$PATH"
pnpm install --frozen-lockfile
pnpm build
```

### 4. 配置 systemd

```bash
sudo cp deploy/dev/litawork-backend.service /etc/systemd/system/litawork-backend.service
sudo systemctl daemon-reload
sudo systemctl enable --now litawork-backend
```

服务日志：`/home/ecs-user/work/litawork/logs/backend.log`。

### 5. 配置 nginx

```bash
sudo cp deploy/dev/nginx.conf /etc/nginx/sites-available/work-test.agent.cinta.team
sudo ln -sf /etc/nginx/sites-available/work-test.agent.cinta.team /etc/nginx/sites-enabled/work-test.agent.cinta.team
sudo rsync -a --delete frontend/dist/ /var/www/work-test.agent.cinta.team/
sudo nginx -t
sudo systemctl reload nginx
```

### 6. 验证

```bash
curl -fsS -o /dev/null http://work-test.agent.cinta.team/api/auth/feishu
curl -fsS http://work-test.agent.cinta.team/ | head
```

首次启动后应用会自动创建业务表并补齐系统任务类型、任务定义与系统机器人。

## 飞书网页登录

网页登录依赖飞书自建应用的 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`，且需要在飞书开放平台登记重定向地址：

```text
http://work-test.agent.cinta.team/api/auth/feishu/callback
```

当前环境配置：

| 项 | 值 |
| --- | --- |
| 飞书应用 | `cli_a92d0c368eb9dcc0`（与生产共用） |
| Lita API | `https://api.test.cinta.team` |
| 登录回调 | `http://work-test.agent.cinta.team/api/auth/feishu/callback` |

`FEISHU_APP_SECRET`、`LITA_USER_TOKEN`、`AUTH_JWT_SECRET` 仅保存在服务器 `backend/.env`，不提交仓库。飞书应用 secret 一旦在聊天或工单中明文传输，建议在飞书后台重置后同步更新 `.env`。

当前 Lita 测试接口仍返回与生产相同的飞书 tenant token，启动时会同步真实通讯录用户；未配置群 webhook 时不会主动发送群消息。如需完全隔离，应改用独立测试租户的应用和令牌。

未配置凭据时，`/login` 会提示登录配置缺失，但 `.md` 接口仍可用 Agent 令牌联调。

## 更新部署

代码合并到 `test` 后执行：

```bash
cd /home/ecs-user/work/litawork
bash deploy/dev/deploy.sh
```

脚本依次执行拉取、安装、后端构建、前端构建、静态发布、systemd/nginx 配置同步、重启服务与健康检查。

## 数据与备份

- 开发库为 `lita_project_dev`，业务数据为空；启动时会从飞书通讯录同步用户目录。
- 重新初始化时可删除并重建数据库，或清空后依赖 `synchronize` 重建表结构。
- 上传文件、导出产物分别位于 `/home/ecs-user/work/litawork/{webroot-images,export-files,files}`。
