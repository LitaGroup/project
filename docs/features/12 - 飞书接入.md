# 飞书接入到 Lita-Work



1、每个机器人对应一个独立的飞书机器人（外部跟它的通信接口） 可选 非必需

有以下几个场景：

1 独立任务的场景：如果需求方和执行方，至少有一方是机器人，两种情况
  一方是机器人：建群，人 + 机器人 + 平台机器人
  两方是机器人：建群，人 + 人 + 平台机器人
2 人和平台机器人直接沟通：直接调用它的助理
3 任务开始上升了
4 任务完成后一天，群自动销毁
5 定制机器人（还是满足绑定飞书）定制其接受飞书消息和指定群消息处理机制的策略（按群指定策略 + 通用策略 - 公共策略）
6 机器人的应答机制 - 触发时机 + 会话传递

任务=群  

### 场景一：飞书的配置

在管理栏目中，左侧增加一个导航：飞书配置，可以为每个机器人配置飞书的 APP ID 和 APP SECRET，允许：自定义机器人 和 个人的AGENT 助理配置，配置后，所有的机器人头像上加个小标，表示有飞书机器人，小标的ICON你自己选一个



并提供一个平台官方机器人的配置方式，表示平台官方的机器人。



飞书的配置存储到数据库中。



### 场景二：真人与机器人在飞书中 一对一 聊天

这个场景，类似于平台内的机器人沟通的场景，直接与机器人所在的AGENT 进行沟通，交互和功能的细节如下：



1. 接受到会话后，插入表情`敲键盘` 表示正在思考和处理中
2. 回复的消息，使用 markdown 消息内容
3. question 使用 飞书的卡片来选项和填写内容
4. 需要支持 图片、文件 的双向通信



### 场景三：平台官方机器人



真人与平台官方机器人的对话，实际是跟这个用户的AGENT 对话。

## 实现状态（第一期）

已落地：

- 管理区「飞书配置」：机器人 / 个人 AGENT 绑定独立飞书应用，平台官方机器人单独配置；Secret 加密落库、只写不回显；机器人列表与头像显示「已连接飞书」角标。
- **事件接收走飞书 WebSocket 长连接**（平台主动连接飞书，无需公网回调地址）；同时保留可选 HTTP 回调端点供具备公网域名的部署使用。
- 一对一聊天：自定义机器人 → 绑定机器人；官方机器人 → 当前用户个人 AGENT；「敲键盘」处理中表情、Markdown 卡片回复、question 卡片（按钮 / 文本 / 跳过）、图片与文件双向通信。
- 任务群：仅「一个真人 + 一个 AI 机器人」的根任务自动建群；官方机器人代理任务 AI；任务终态发送结果卡片，24 小时后自动解散；群内 @官方机器人 的消息走任务中心。
- 用户身份映射：按「飞书配置 + open_id」缓存，首次用 union_id / 同应用 open_id 匹配，未识别用户回复绑定引导。

暂缓（后续补充）：

- 两方都是机器人的任务群。
- 群内非 @ 消息的持续上下文接收、按群指定的应答策略、工具/思考过程同步。
- 任务执行中间状态的群内实时镜像（当前为建群卡片 + 终态卡片）。
- 独立飞书应用与平台 OAuth 应用不同时的完整账号绑定流程（当前依赖 union_id / 同应用 open_id）。
