# 任务相关的技能

为 AI Agent 提供任务相关的技能接口，完成任务的能力。已实现任务识别的读取/更新与任务验收的申请/反馈四个技能。

- 任务识别接口使用用户 Agent 令牌 `X-Agent-Token`。
- 验收申请接口使用机器人独立令牌 `X-Worker-Token`，令牌由平台在首次派发时写入工位 `.opencode/agent-token`。
- 验收反馈接口使用需求方用户的 `X-Agent-Token` 或网页登录会话，且只允许任务创建人操作；子任务回退根任务创建人。

## task-recognize-detail: 任务识别与分发技能

参数：任务 ID。

```http
GET /api/tasks/{taskId}/recognize.md
X-Agent-Token: {TOKEN}
```

返回 `text/markdown`：

1. 任务详情：ID、编号、标题、类型、描述、任务输入（用户原始需求）、需求内容（AI 分析整理）、交付方式（`outputSpec`）、工作计划
2. 任务状态：主状态与子状态，以及当前执行机器人
3. 时间：创建时间、更新时间（北京时间）
4. 当前的有效机器人清单：启用中的「工作者」机器人，每项包括机器人 ID、名称、描述

## task-recognize-update: 任务识别更新

参数：任务 ID、任务标题、需求内容、交付方式、任务计划；可选补充原始需求（input）与执行机器人 ID。

```http
POST /api/tasks/{taskId}/recognize.md
Content-Type: application/json
X-Agent-Token: {TOKEN}
```

```json
{
  "title": "任务标题",
  "input": "用户的原始需求，可选；不传保留原值，传空值或 null 清除",
  "content": "需求内容（必填）：Agent AI 分析整理后的需求内容，包括需求澄清和补充的详细信息",
  "outputSpec": "交付方式",
  "workPlan": "1. 第一步\n2. 第二步",
  "agentId": 1001
}
```

返回：成功时返回 `text/markdown` 更新结果；失败时返回 400/404 与具体原因。

- `title`、`content`（需求内容）、`outputSpec`（交付方式）、`workPlan`（任务计划）必填
- `input`（用户的原始需求）可选：不传保留原值，传空值或 `null` 清除
- `agentId` 可选：不传保留原分配，传 `null` 清除；传 ID 时机器人必须存在、启用且为「工作者」
- 只保存识别结果，不改变任务状态、不派发执行、不创建子任务

## task-deliver-apply: 任务验收申请

执行机器人完成交付后主动申请验收。**会话执行成功不会自动进入待验收**，未调用该接口时任务保持「进行中-执行中」。

```http
POST /api/tasks/{taskId}/handoff/apply.md
X-Worker-Token: {WORKER_TOKEN}
Content-Type: application/json
```

```json
{
  "delivery": "交付结果、代码仓库/分支、文档清单",
  "problems": "实现问题与解决",
  "detours": "走过的弯路",
  "lessons": "经验总结",
  "followUps": "遗留建议与后续待办",
  "other": "其它需要保留的信息"
}
```

- 只接受机器人独立令牌，不接受用户 `X-Agent-Token` 或网页会话代替
- 令牌对应机器人必须等于任务当前 `agentId`；任务重新分配后原机器人返回 403
- 只允许「进行中-执行中」；旧 `deliver/apply.md` 保留兼容
- 请求体六个字段均可选，无 body 的旧调用兼容；代码交付必须写仓库和分支，文档交付必须写名称及路径/链接，没有的内容明确写“无”
- 先生成或覆盖交付文档 `task/{date}/{task-id}/HANDOFF`（知识路径不带 `.md` 后缀），统一按「0 任务与责任 / 1 需求说明 / 2 交付内容 / 3 实现问题与解决 / 4 弯路与经验复盘 / 5 遗留建议与后续待办 / 6 其它需要保留的信息」组织；写入失败时申请验收失败，任务保持「进行中-执行中」
- 保存本轮执行产出，状态流转为「等待中-待验收」，并通知任务需求方；交付说明与需求方名称随事件留存，供验收后的 REVIEW 复用
- 返回 `text/markdown`（含交付文档路径）；无权限 403、状态不允许 400、任务不存在 404

机器人派发时平台会把令牌写入工位 `.opencode/agent-token`（权限 600），机器人调用示例：

```bash
TOKEN=$(cat .opencode/agent-token)
curl -sS -X POST {API_URL}/tasks/{taskId}/handoff/apply.md \
  -H "X-Worker-Token: $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"delivery":"分支 test；文档 /project/8/document/9","problems":"无","detours":"无","lessons":"无","followUps":"无","other":"无"}'
```

## task-deliver-reply: 任务验收反馈

任务需求方处理验收申请。只允许任务创建用户调用；子任务未记录创建人时回退根任务创建人。公共 Agent 令牌和管理员身份不能绕过需求方校验。

### 通过验收

```http
POST /api/tasks/{taskId}/deliver/reply.md
Content-Type: application/json
X-Agent-Token: {USER_TOKEN}
```

```json
{ "action": "accept" }
```

- 仅允许「等待中-待验收」
- 状态流转为「已结束-完成」，记录验收人和时间
- 异步生成 `task/{date}/{task-id}/REVIEW` 复盘文档（知识路径不带 `.md` 后缀），并销毁原任务执行器会话

### 拒绝验收

```json
{
  "action": "refuse",
  "content": "页面缺少加载状态，请补充后重新申请验收"
}
```

- `content` 必填，空内容返回 400
- 反馈写入任务事件与对话，任务状态变更为「进行中-执行中」
- 使用原执行机器人和原任务会话重新执行；完成后需再次调用 `task-deliver-apply`
