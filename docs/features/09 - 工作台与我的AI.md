# 工作台与我的 AI

## 概念

- **我**：当前登录用户的代理机器人。
- **真人机器人**：`workers.humanUserId` 唯一绑定用户，runtime=human，代表用户作为任务执行者。
- **个人 AI AGENT**：`workers.personalAgentUserId` 唯一绑定用户，runtime=opencode，代表用户在工作台与任务中行动。

## 工作台受理范围

工作台只列出「我」作为以下角色的任务：

1. **发起者 / 需求方**：真人机器人、个人 AGENT 或用户本人是任务 `requester`。
2. **执行方**：真人机器人或个人 AGENT 是任务 `agentId`；或任务执行机器人 `ownerUserId` 是当前用户；或验收升级后 `ownerTakeoverUserId` 是当前用户。
3. **参与者**：预留，后续补充。

任务项附带 `workbenchRoles`：

- `agent`：我的真人机器人执行，可手动接受/回复/交付；
- `owner`：我的个人 AI 执行，用户监督进度；
- `requester`：我是需求方，可答复提问/验收/返工/判失败；
- `responsible`：我是执行机器人负责人或已接管任务，可跟进并提交反馈（我正在任务中同时是需求方时不叠加，执行身份以需求方 TAB 为准）。

## 右侧 AI 工作台

TAB 按当前用户在任务中的角色动态展示：

- **任务-需求方**：`workbenchRoles` 含 `requester` 时展示；
- **任务-执行方**：含 `agent` / `owner` / `responsible` 时展示；
- **我的AI**：常驻。

两个任务 TAB 展示同一份任务消息记录，但操作身份固定跟随 TAB，避免同一用户既是需求方又是执行方时混淆：

- **任务-需求方**：发送消息始终作为需求补充；待验收时作为验收不通过。仅展示验收通过、新子任务、分配任务、取消任务、重新生成复盘，并允许回答执行方提问。
- **任务-执行方**：执行中可发送真人执行回复或执行器续聊；仅展示发起交付（待验收时为撤销交付）、分配任务、新子任务、拒绝任务。待验收时禁止以执行方身份发送普通消息，需先撤销交付。发起交付弹窗只确认当前交付文档版本，不再编辑正文；交付文档在左侧「交付文档」面板由需求方/真人执行方共同维护，内容变化后版本递增，需求方修改会通知 AI 读取最新版本。
- 消息携带 `perspective=requester|responsible`，工作台按当前 TAB 决定左右布局：本身份消息靠右、另一方靠左；发送者角色标签统一为「需求方 / 执行方」。
- 创建子任务携带当前 TAB 的 `perspective=requester|responsible`，后端按该身份校验并确定子任务需求方。

### 我的 AI

直接与当前用户的个人 AI AGENT 多轮对话：

- **每个任务独立 SESSION**：`worker_debug_sessions` 按「用户 + 机器人 + contextKey」绑定，任务会话为 `agent:task:{taskId}`，未选任务使用 `agent:global`，与机器人调试 `debug` 互不影响；切换任务时重新拉快照并重连 SSE，7 天不活跃重置；
- SSE：`GET /api/workbench/agent/stream?taskId=`；
- 发送消息携带当前选中的 `taskId`，后端把任务上下文放入本轮提示词，但不写入用户气泡；
- **固定使用 Build 模式**：主 Agent 固定为 `build`，不提供 Build / Plan 切换；历史 Plan 会话在下一条消息前自动切回 `build`；
- 模型与思考等级按会话保存（`POST /api/workbench/agent/model`）；
- AGENT 通过平台 `.md` 接口与技能操作任务：
  - `GET /api/tasks.md?scope=mine`：我的任务清单；
  - `GET /api/tasks/{id}.md`：任务详情；
  - `POST /api/tasks/create.md`：创建任务；
  - 以及既有的接受/拒绝/提问/答复/交付/验收/返工/失败/子任务/工单转交接口。

> 个人 AI AGENT 只负责「我的 AI」对话与代表用户操作任务；**任务的实际执行仍由真人机器人（`workers.humanUserId`）承担**。

## 个人 AGENT 的创建

- 登录与打开工作台时由 `PersonalAgentsService.ensureForUser` 懒创建；
- 复制系统调度机器人（优先）或首个启用且在线工作者的执行器/默认模型/思考等级；
- 自动生成角色定义（含任务 API 与操作约定），异步安装 `project-manage` 等技能并初始化工位；
- 令牌写入工位 `.opencode/.env` 与 `.opencode/agent-token`，AGENT 以机器人身份操作平台；
- AGENT 创建的任务需求方是 AGENT 自己；工作台通过 `personalAgentUserId` 映射到绑定用户，用户可直接验收。

## 个人中心导航

从右上角用户下拉进入个人中心后，左侧导航固定为：

- 个人中心（`/profile`）
- 我的代理（`/profile/robot`）

个人中心不占顶部顶级 Tab，也不复用项目区左侧导航。

## 我的代理（配置入口）

- 入口：右上角用户下拉「个人中心」下方的「我的代理」（`/profile/robot`）；
- 编辑对象就是「我的 AI」实际对话的个人 AI AGENT（`workers.personalAgentUserId`）；
- 可配置：技能、规范、AGENTS.md（机器人定义）、执行器、默认模型（供应商/模型/思考等级合并为一个可搜索的选择面板）；名称、头像、简介、上级、启停等任务机器人字段隐藏；
- 保存后按现有初始化流程同步工位（AGENTS.md、`.opencode/skills`、`.opencode/rules`）；
- 该机器人不承担任务执行；任务执行由真人机器人负责。
